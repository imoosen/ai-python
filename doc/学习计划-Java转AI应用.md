# Java 高工转 AI 应用工程师 · 三个月学习计划

> **目标定位**:AI 应用工程师(LLM + RAG + Agent 工程化),不是 AI 研究员。
> **核心差异**:用工程能力把 LLM 的不确定性关进生产级框架里。
> **关键假设**:每周投入 15–20 小时,总计 180–240 小时。

---

## 一、你是 Java 高工的真实优势(先盘清楚,别从零学)

你以为是转行,其实是**能力的迁移**。下面这些你已经会的,AI 应用工程同样需要,不需要重新学:

| 你已经会的 | AI 应用里对应的东西 | 为什么不是重新学 |
|---|---|---|
| 分布式系统设计 | Agent 状态机、Controller | 编排思维一致 |
| 幂等 / 重试 / 超时 | LLM 调用加固 | 概念完全相同 |
| 设计模式 | Agent 架构六模式(Chaining / Routing / Orchestrator-Workers 等) | 直接迁移 |
| 消息队列 / 异步 | Agent 异步任务、工具调用并发 | 模型一致 |
| 日志 / Trace / Metrics | LLM 应用可观测性 | 思路一致,工具换了 |
| 代码质量意识 | Prompt 版本管理、评测集 | 你懂"配置即代码" |

**真正要补的(只有 4 块)**:
1. **Python**(1 周速成,你 Java 扎实 → 两天过语法,三天写工程)
2. **LLM 原理 + API 实战**(这是新东西,但不需要数学推导)
3. **AI 工程化工具链**(LangChain/LangGraph、向量库、可观测性)
4. **评测 + 成本控制**(LLM 的概率性带来的新维度)

## 二、三个月分阶段路线图

### Month 1:基础与原理(Week 1–4)— 60–80h

**Week 1 · Python 速成 + 工程环境**
- 目标:能在 Python 里写 CLI 工具、调通 LLM API
- 产出:`hello-llm.py`,输入一句话,输出 LLM 回应
- 关键内容:
  - Python 语法速过(Java 高工 2 天过完)
  - venv、pip、项目结构(参考 `/Users/apple/.workbuddy/binaries/python/envs/default` 隔离环境)
  - 主流 LLM SDK 选型:OpenAI 兼容协议 → DeepSeek / 通义千问 / 豆包都能用一套代码
- 验证:`python hello-llm.py` 跑通,看到 LLM 输出

**Week 2 · LLM 原理速览 + 模型生态**
- 目标:理解 Token / 上下文窗口 / 温度 / Function Calling 是怎么回事
- 产出:一张"主流 LLM 对比表"(放你工作目录)
- 关键内容:
  - Transformer 概念(不推公式,讲清"自注意力是啥")
  - Token 计费原理、上下文窗口限制
  - 主流模型横评:DeepSeek-V3 / Claude / GPT-4o / 豆包 / 通义千问
  - **关键决策**:默认用 DeepSeek(国内便宜、中文好、OpenAI 兼容),需要高级能力时少量用 Claude/GPT
- 验证:能口头说清"为什么同一个问题,温度 0 和 1 答案不同"

**Week 3 · Prompt 工程基础**
- 目标:掌握 6 种核心 Prompt 模式
- 产出:每个模式的示例代码 + 评测对比
- 关键内容:
  - Zero-shot / Few-shot / CoT(思维链)
  - ReAct(推理+行动)— 这是 Agent 的雏形
  - System Prompt 结构化写法
  - Prompt 版本化管理(用 Git,这是你最熟的)
- 验证:同一任务,用 CoT 比 Zero-shot 准确率明显提升(有数字)

**Week 4 · Function Calling + 第一个小项目**
- 目标:让 LLM 调用外部工具
- 产出:**剪映工程文件摘要工具**(结合你的实际场景)
  - 输入:剪映工程 JSON / 字幕文件
  - LLM 解析:自动生成视频摘要、章节切片建议
- 关键内容:
  - OpenAI 兼容 Function Calling 协议
  - JSON Schema 工具定义
  - 工具参数校验、错误处理(你 Java 熟的 try/catch → Python except)
- 验证:工具能跑通,你拿自己一个真实剪映工程测试

### Month 2:核心能力(Week 5–8)— 80–100h

**Week 5 · RAG 架构(检索增强生成)**
- 目标:理解为什么"塞进 Prompt"不够,需要向量检索
- 产出:技术选型表(向量库 / Embedding 模型 / 分块策略)
- 关键内容:
  - Embedding 原理(把文本变向量,语义相似检索)
  - 主流向量库横评:Chroma(本地)/ Qdrant / Milvus / Pinecone
  - 分块(Chunk)策略:固定长度 / 语义分块 / 重叠窗口
  - 召回 + 重排两阶段架构
- 验证:能讲清"为什么召回 100 条再重排到 5 条,比直接召回 5 条准"

**Week 6 · RAG 实战项目**
- 目标:做一个**你自己的文档问答系统**
- 产出:`docs-qa` 项目(部署可访问)
  - 数据源:你自己的笔记 / 收藏 / 选购速查表
  - 能回答"我之前选 Mac 时怎么考虑的?"这类问题
- 关键内容:
  - 文档加载(支持 PDF / Markdown / 网页)
  - Embedding 批处理、断点续传(你的工程化能力上场)
  - 检索 + Prompt 拼接
  - 流式输出(SSE / WebSocket)
- 验证:用自己 5 个真实问题测试,准确率 ≥ 80%

**Week 7 · Agent 框架(LangChain + LangGraph)**
- 目标:理解"Agent ≠ Chatbot"的本质差异
- 产出:技术笔记 + 第一个 LangGraph 图
- 关键内容:
  - LangChain 基础(Chain / Tool / Memory / Retriever)
  - **LangGraph**(重点):用图定义 Agent 状态机
  - Agent 架构六模式(Chaining / Routing / Parallelization / Orchestrator-Workers / Evaluator-Optimizer / Autonomous Loop)
  - **必看材料**:Anthropic 的"Building Effective Agents"博客(免费,讲清楚了)
- 验证:能用 LangGraph 画一个三节点的 Agent 流程图,跑通

**Week 8 · Agent 实战(工具调用 + 记忆)**
- 目标:做一个**真实可用的 Agent**
- 产出:**视频脚本生成 Agent**(结合你的实际工作)
  - 输入:一个选题
  - Agent 流程:检索已有素材 → 生成大纲 → 调用即梦 API 生成首帧图 → 输出脚本 + 配图
- 关键内容:
  - 多工具编排(检索 + 文生图 + 文件写入)
  - 短期记忆(对话上下文)vs 长期记忆(向量库持久化)
  - Token 预算控制(你的"卡死预算"思维上场)
  - **安全**:危险操作必须 human-in-the-loop 二次确认
- 验证:用你下一个视频选题,完整跑通 Agent

### Month 3:实战与生产化(Week 9–12)— 80–100h

**Week 9 · 可观测性(LangSmith / Langfuse)**
- 目标:让 Agent 跑得"看得见"
- 产出:接入了 Langfuse 的 Agent,可看 trace
- 关键内容:
  - Trace / Span / Token 用量监控
  - 工具调用成功率、P95 延迟
  - 成本看板(每条对话花了多少钱)
  - **这是你的差异化优势**:Java 高工的"日志/Trace 经验"直接迁移
- 验证:跑 50 个测试,看 trace 找出至少 1 个优化点

**Week 10 · 评测体系(最被忽视但最关键)**
- 目标:从"能跑"到"能信"
- 产出:**≥ 20 条评测集**(覆盖正常 / 边界 / 对抗)
- 关键内容:
  - 评测集设计:正常用例 / 边界用例 / 提示注入 / 越权工具调用 / 超长输入
  - 评分方式:LLM-as-Judge + 人工抽检
  - 通过线:核心场景 ≥ 95%,对抗场景 100% 拦截
  - **回归测试**:每次改 Prompt 跑一遍评测集
- 验证:你的评测集能在 5 分钟内告诉你"这次改动是好了还是差了"

**Week 11 · 端到端项目(可上简历)**
- 目标:交付一个**生产级** Agent 系统
- 产出:**候选项目(选 1)**:
  - A. **AI 短剧剧本 Agent**(接你现有工作流:DeepSeek + 即梦 + 豆包)
  - B. **Mac 选购顾问 Agent**(用你自己的速查表做 RAG,回答"我该买哪台 Mac")
  - C. **剪映剪辑助手**(解析剪映工程,自动切片、配字幕建议)
- 必含特性:
  - 部署可访问(用 CloudStudio / Vercel / 自部署)
  - 有 README、有 trace、有评测
  - 有 Git 提交历史(展示过程)
- 验证:陌生人能跑通你的项目、看到效果

**Week 12 · 作品集 + 求职/转型准备**
- 目标:从"学完了"到"被认可"
- 产出清单:
  - GitHub 仓库(代码可读、README 有架构图)
  - 1 篇技术博客(总结学习心得,发掘金 / 知乎)
  - 简历更新(Java 高工 + AI 应用工程师双重身份)
  - 模拟面试题清单(20 题,你能用 5 分钟讲清一个 Agent 系统的设计取舍)
- 验证:给一个不懂 AI 的 Java 同事讲 Agent,他能听懂

## 五、避坑指南(提前说,省你踩坑时间)

1. **不要先去学 ML 理论**(Transformer 数学、注意力公式)— 应用工程师不需要
2. **不要买大课**(几千块的"AI 全栈课")— 文档 + 开源项目 > 大课
3. **不要一上来就 LangChain 全家桶**— 先用裸 API 跑通,再加框架
4. **不要追新模型**(每天看新闻会分散精力)— 主用一个,其他了解即可
5. **不要忽略评测**(很多人学完发现"Prompt 改了不知道变好还是变差")— Week 10 必学
6. **不要做"无所不知"的 Agent**— 围绕你的真实场景做(剪映 / 短剧 / 选购),别做"通用聊天机器人"
